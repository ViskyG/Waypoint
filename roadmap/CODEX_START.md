Не повторяйте завершённые пакеты по старому начальному frontier и не принимайте количество зелёных критериев за полноту контракта.

Источник структуры — `ROADMAP.plan.json`. Текущее состояние исполнения, история и подтверждения результатов — в действующем Waypoint. Перед новым изменением проверьте Git и текущий head, экспортируйте свежую карту и используйте её `base_version` со стабильным `request_id`. Не заменяйте рабочую БД архивной копией. Старые инструкции сохранены в `history/`.

Для задачи прочитайте её пакет и точный набор источников. В новых пакетах `reference_root: ../next-stage` разрешает пути исходного архива; для старых пакетов сохраняется прежняя база. Общие файлы меняет один интегратор; независимые области можно делегировать. Применяйте канонический `execute-roadmap-efficiently` через `skill-navigation`, не изменяя глобальные скилы без разрешения.

Waypoint — пассивный наблюдатель. Статус done не подтверждает наличие результата: typed requires проверяются общим resolver по неизменяемым свидетельствам, ревизии и рабочей копии. Не скрывайте unknown, conflict или позднее получение.

При начале работы над блоком отправьте `focus` через собственную проверенную привязку. Каждый подагент использует свой native ID и свою привязку; привязка родителя не наследуется. При смене блока достаточно одного нового сигнала области. Без этого настоящие сообщения сохраняются в потоке агента, но их связь с блоком остаётся неизвестной. Не восстанавливайте такую связь задним числом по догадке.

После проверки запишите `test.result` с существующим ID критерия, run_id и точным основанием. Отделяйте автоматический тест, ручной осмотр, синтетический HTTP-сценарий и проверку настоящего Codex. Позднюю регистрацию из сохранённого отчёта помечайте явно; её время не заменяет неизвестное время старого запуска. До завершения пакета проверьте, что в его UI видны результат и сохранённые проверки. Сообщения, статус и доказательства остаются отдельными данными.

N09 доступен только после подтверждения отдельного третьего графического референса. Его отсутствие не блокирует независимый ремонт; N08 сейчас требует исправлений по отдельным находкам аудита. Предложенные изменения скилов подготовлены локально и не установлены глобально. После передачи или завершения снимайте собственный focus, не оставляя будущие сообщения в закрытом блоке.
