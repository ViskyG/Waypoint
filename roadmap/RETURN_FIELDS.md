# Возврат результата исполнения карты

Дополнить существующий `../waypoint/reports/RETURN_TO_CHAT_RU.md`, не создавать вторую систему статусов.

Для выбранного пакета/этапа указать: ID; реальную исходную базу и итоговую ревизию/manifest; фактические изменённые пути; ожидаемый и полученный результат; расхождения; IDs проверок и их исходы, окружение/команды/артефакты; что переиспользовано и почему осталось применимым; NOT_RUN/INCONCLUSIVE с конкретной причиной.

Для карты указать: project_id; предыдущий и новый **реальные** plan_version; была ли применена правка или только подготовлена; request_id/receipt; экспортированный snapshot. Не записывать авторский номер `2026-10-16-r1` вместо настоящего `v-…` Store.

Для исполнения указать: правильный native agent ID проверен или неизвестен; текущие bindings не наследуются родителем вслепую; какой scope закончился; какие следующие пакеты действительно доступны. Не принимать `preferred_executor` из карты за сделанный claim.

Для публикации раздельно: файл создан; сохранён в Library; перенесён в Drive/Git; registry/inbox обновлён; skill опубликован; runtime binding установлен; наблюдение работает; пользователь принял. Только выполненные операции помечать выполненными.

Возвращать агрегаты/типы/равенства идентификаторов и безопасные примеры. Реальные тексты переписок, HOME/auth/config, полная SQLite и ключи исключаются. Скан шаблонов секретов — помощь, не универсальное доказательство отсутствия любых чувствительных сведений.
