# Waypoint — следующий этап: понятная карта, план и алгоритмы

**Готовый пакет проектирования и дорожная карта для Codex. Режим MIXED.**
Это не реализованное обновление и не новая исходная кодовая база.
Главная инструкция — **CODEX_START.md в корне этого архива**.

## Что меняется
Человекочитаемое «Задание» с отдельной технической подвкладкой; каталог проектов;
единая вкладка «План» со статусами блоков; фильтры типов сообщений; действительные
предпосылки работы с объяснимыми свидетельствами; реестр значимых собственных
алгоритмов, их кода, проверок и оптимизаций; расширяемые темы с сохранением
требования трёх выбранных оформлений.

Все представления используют один граф и одни события. Waypoint не управляет
исполнителями, не переписывает их статусы и не требует дополнительной отчётности
ради плана. Капсулы чата — опциональный способ получить результат, не зависимость
дорожной карты. Codex может исполнить всю карту без ожидания ChatGPT.

## Куда смотреть
- `design/DESIGN.md` — решения и объяснение пользовательского поведения.
- `design/CONTRACTS.md` — точные поля, события, API и алгоритмические правила.
- `design/IMPLEMENTATION.md` — границы кода, совместимость, миграция и владение.
- `roadmap/ROADMAP.plan.json` — единственный исходник задач нового этапа.
- `roadmap/ROADMAP.md`, `roadmap/packets/`, `roadmap/PREVIEW.html` — его производные.
- `skills/` — точечные EN/RU поправки к пяти существующим скилам и безопасная подготовка кандидатов. Они НЕ опубликованы и НЕ установлены.
- `design/ACCEPTANCE.md` — проверки, включая обязательную целевую приёмку.
- `evidence/VALIDATION.json` — только проверки этого пакета, не продукта.

## Исходная база
Проектирование привязано к проверенному `ViskyG/Waypoint@c36e2e9a296ec8a78e4a19fad1975ea6ed951ade`.
Прежние C01–C07 не заказываются заново. Перед работой сравнить фактическую копию
с указанной базой. Архив не содержит старую полную программу, чтобы не затереть
новую реализацию. Нужен доступ к существующей рабочей копии Waypoint.

## Дорожная карта
N00 — проверить рабочую базу; N01 — общий профиль/миграция; N02 — зависимости;
N03 — каталог/план/задание; N04 — фильтры; N05 — алгоритмы; N06 — реестр тем;
N07 — профиль авторства и правки скилов; N08 — цельная приёмка; N09 — третья тема.
У каждого пакета есть точное чтение, файлы/логические границы, входные результаты,
проверки и следующий допустимый шаг. Общие файлы нельзя редактировать параллельно
без единственного интегратора; рекомендация порядка владения не маскируется ребром-блокером.

## Единственная незакрытая пользовательская деталь
Для третьей отличающейся темы нужен её референс. Два из трёх доступных вложений
побайтно совпадают. Это НЕ отменяет третью тему и НЕ блокирует остальные пакеты.
N08 допускает отчёт о готовности функциональной части с открытым N09; весь запрос
не объявляется принятым до третьей темы. Причина старого эпизода раннего старта
тоже не выдумывается: нужны конкретные IDs/события, если они сохранились.

## Проверка архива
Из его корня: `python3 tools/check_package.py`.
Контрактные модели: `python3 -m unittest discover -s tests -v`.
Обе команды локальные, без модели, сети и записи в рабочий проект.
