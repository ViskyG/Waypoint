# Direct roadmap execution
Navigation: project-workflow. Required: selected resource policy, current roadmap frontier/packet, workflow-state-and-transit P1, P4, P7-P8, evidence-driven-validation. Udot owns cross-executor orchestration.


Use this route only when direct Codex development is authorized. ECONOMICAL does not become permissive because an edit is awkward; an indispensable infrastructure bridge/repair is a distinct bounded task, not permission for general project work. Never substitute Work or another paid API.


Begin from compact runtime state and the current packet, not the full repository/roadmap. Read exact required source/contracts and only the rationale genuinely needed. Check relevant target contents to avoid overwriting others; do not ritual-audit the project before editing.


Respect live chat claims, design-session embargo and Udot's incoming-change notices. Do not duplicate implementation already produced or underway. Prefer another exposed independent task when a capsule is coming. On unavoidable shared-file/anchor overlap, coordinate the integration order with Udot before replacing it.


Implement a coherent unit within accepted architecture/contracts. Ordinary local naming, helpers, fixtures and equivalent implementation details are delegated; central contracts or requirements are not. Use stable file ownership and logical anchors, not brittle line numbers or global find-and-replace over unrelated code.


Run only the evidence justified by the packet/change. Existing applicable evidence can be reused; direct observable behavior can suffice for a specific claim. Do not run broad regressions or self-audits repeatedly on unchanged relevant state. Record real checks versus NOT_RUN and preserve diagnostics from failures.


During long builds/tests/provisioning, switch to a safe independent frontier task rather than polling or rerunning the same operation. Do not mutate a shared unstable base while a check assumes it is frozen. If no independent task exists, record the actual dependency instead of inventing busywork.


At coherent checkpoints preserve code through the project's commit/push/publication policy and update compact state/evidence for Udot. Keep unrelated edits out. On an unexpected material contradiction, preserve exact evidence and safe progress, escalate the affected branch and continue unaffected work.


If a task requires Pro-level reasoning, explicitly request the user switch this Codex session to Pro or bring a completed Pro-chat capsule. Preserve the bounded context/handoff and perform other safe work; do not secretly invoke another model or spend the prohibited budget.


On the machine's return after offline accumulation, do not resume mutations until Udot's synchronization barrier has established the workspace baseline. Apply revised plans only to affected work, preserving unchanged completed code and evidence. Finish with actual implementation/publication/evidence status, not a generic "all green".



## Input evidence and observed algorithm changes
Before dependent work, use the current packet's effective prerequisites and check
that the required output is available in the relevant workspace. Free status text
or a collapsed parent arrow alone is insufficient. If an edge is inaccurate,
revise its bounded contract or record an explained deviation; preserve actual
work and unknown evidence. The observer is not an execution authority.

At meaningful changes to a registered custom algorithm, update exact implementation
and affected test/measurement references. Separate authored tests, executed evidence,
correctness and resource claims. A changed implementation can make evidence stale;
it does not make an old run fail. Do not declare an optimization measured without
compatible data/method evidence. Do not maintain a second Plan status document or
ask the model to summarize streams merely to refresh the UI. These rules preserve
optional chat supply and the already selected resource permissions.

## Waypoint execution trace and completion evidence
When Waypoint observation is in scope, follow the owning project's workflow contract.
Before implementation, validate this executor's own native binding and declare the
packet scope. Each child does this with its own identity; never copy a parent's
binding or rely on a shared session ID. A missing binding leaves native messages
unassigned; resolve it once without inventing attribution or blocking unrelated
permitted work. Scope is observational, not an exclusive claim or agent control.

At meaningful check boundaries record the actual outcome against existing criterion
IDs with run ID, immutable evidence reference and applicable revision/environment.
Register executed checks before reporting the packet complete. Reused evidence
retains its original run basis; retrospective registration says it is retrospective,
without an invented past timestamp. Distinguish skipped/not_run, failed/error and
unverified claims. A manual --current declaration is not automatic verification of
current code. Empty chat proves neither success nor failure. Never add synthetic
notes, guessed historical links or repeated tests just to fill the map.

Before done, compare the packet's expected result and criteria with the observed
result. Record exceptions, missing checks and the smallest remaining fix explicitly;
partial delivery may be described honestly without calling it accepted. Completion
records do not close focus automatically: release or redeclare this executor's scope
at handoff. Preserve original events and IDs. No heartbeat, extra model polling,
permission gate, global installation or start/resume/stop command is introduced.
