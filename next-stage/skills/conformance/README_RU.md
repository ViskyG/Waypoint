# Исправления скилов после проверки соответствия

Подготовлены три ограниченных кандидата для канонических ролей: исполнитель Codex, проектировщик дорожной карты и аудитор. Основой служат фактически прочитанные файлы `/home/visky/Work/agent-skills`, все версии 2.0.0. Сохранены точные исходные SHA-256 и Git blob, локальные снимки и unified patches. Английские кандидаты 2.0.1 включают прежние неподключённые дополнения observability/1 для исполнения/планирования и новые правила достоверной истории. Русские файлы — параллельные дополнения, а не вымышленный полный перевод отсутствующего перевода.

Глобальный checkout не изменён. Кандидаты **не опубликованы, не установлены и не зарегистрированы**. Прежние предложения `../candidates` сохранены как исторические, а не выданы за применённые версии. Для проверки и возможного отдельного применения используются `STAGING.json`, `bases/`, `candidates/`, `patches/`, `amendments/`.

В собственном проекте обновлены четыре черновика `waypoint-observe`/`waypoint-map` EN/RU до 0.3.0: сохранены предыдущие правила, включено накопленное дополнение 0.2 и добавлена дисциплина подтверждённой области, проверок, завершения и передачи. Их статус остаётся `draft-candidate`; обновление файлов проекта не является глобальной установкой. Старый тест предложений 0.2 теперь сверяет историческую поставку 0.1 по исходному Git blob в `next-stage/sources/project-skills`, а не текущий изменяемый черновик.

Общий [WAYPOINT_WORKFLOW.md](WAYPOINT_WORKFLOW.md) содержит точные существующие команды и распределение обязанностей. Он закрывает организационные причины аудита: отсутствие собственных областей подагентов, поздние проверки, неснятый focus, подмену исторического доказательства текущим файлом, ручную трактовку freshness и чрезмерный вывод из количества зелёных отметок. Он не добавляет агентный контроллер, программный тестовый барьер или новые разрешения.

Выполнены только адресные проверки скилов и грамматики CLI. Проверены сохранение канонических исходников, ограниченность патчей, сохранение прошлых дополнений/чернового статуса, разбор всех команд документа, отдельное снятие focus, ручная freshness и явная поздняя регистрация. Это проверка контрактов инструкций и функций формирования событий, **не доказательство поведения будущей модели, настоящего binding или живой интеграции Codex**. История одного исправленного тестового ожидания ISO-времени отражена в `VALIDATION.json`; продуктовый код не менялся. Предыдущие продуктовые доказательства не перепроверялись.

Дополнительно `skill-creator` проверил структуру пяти английских entrypoint: три общих кандидата и два проектных скила. Все прошли; [QUICK_VALIDATION.json](QUICK_VALIDATION.json) ограничивает вывод форматом frontmatter и сохраняет причину выбора системного Python с уже установленным PyYAML. Проверки не требовали установки зависимостей или изменения глобальных файлов.
