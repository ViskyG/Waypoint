## Достоверная история участка
Точные команды приведены в [контракте проекта](../../../next-stage/skills/conformance/WAYPOINT_WORKFLOW.md).
До работы проверь собственную привязку и объяви focus; каждый подагент использует
свой ID, не привязку родителя. После done или передачи сними либо смени focus:
само завершение область не снимает. Не угадывай тему старых сообщений для привязки.

До завершения запиши фактические результаты по существующим ID критериев, включая
уместные отрицательные сценарии. Укажи run ID, неизменяемое доказательство и
ревизию/рабочую область/среду. Повторное использование сохраняет исходный запуск.
Поздняя регистрация отмечается явно и не выдумывает старое время. --current — ручная
оценка свежести, не проверка хеша кода. Разделяй настоящий Codex, синтетический
HTTP/браузер и mocked проверки.

Сопоставь ожидание и факт, честно обозначь недостающие/неуспешные проверки, частичный
результат либо связанный ремонт. Число зелёных отметок и пустой чат не доказывают
приёмку продукта. Не повторяй тесты и не пересказывай чат ради наполнения панелей;
не вводи heartbeat и управление агентами. Статус скила остаётся draft-candidate.
