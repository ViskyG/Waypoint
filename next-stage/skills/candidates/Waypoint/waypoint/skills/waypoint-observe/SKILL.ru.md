# Наблюдение без отдельной работы на наблюдателя

Кандидат версии 0.2.0, не установлен и не зарегистрирован глобально.

Используй текущий проект и **отдельный ID своего агента**, полученный проверенной интеграцией исполнителя. В испытанном Codex это `payload.id`; общий `session_id` и унаследованная привязка родителя не подходят. Если привязка неизвестна, оставь сообщения без привязки к блоку и один раз установи собственную идентичность через установленную интеграцию. Не выдумывай ID и не приписывай работу потомка родителю.

При смене рабочего участка отправляй одну команду:

```bash
wp --project PROJECT --agent codex/NATIVE_ID focus W-02 W-03
```

Пустой focus снимает привязку. Можно указать несколько блоков или работу вне карты; исключительного резервирования нет. Сообщения и инструменты собираются автоматически. Не пересказывай их для Waypoint, не отправляй постоянные heartbeat, не спрашивай модель о статусе и не перечитывай всю карту. Для нужного участка получай компактное задание через `wp --project PROJECT packet W-02`.

На содержательных границах статуса, проверки или результата используй `status`, `test`, `done`. Они описывают наблюдения, а не разрешение продолжать. По возможности объединяй сигнал с обычной рабочей командой. У результата теста должны быть действительный запуск, исход и основание; незапущенный тест не зелёный. Done может сосуществовать с неуспешными тестами при явном пояснении исполнителя. Ожидаемый/фактический результат и расхождение запиши через `done --result TEXT --diff TEXT`; не переписывай молча критерии приёмки.

`QUEUED_LOCALLY` значит, что сигнал сохранён в локальной очереди, но ещё не доставлен интерфейсу. Сбой телеметрии не должен останавливать настоящую задачу: сохрани пропущенный сигнал один раз и продолжай разрешённую работу. Некорректное изменение плана и конфликт ID операции — другой случай: не объявляй их применёнными. Не запускай цикл повторов, расходующий inference.

Наблюдатель не посылает агентам start/resume/steer/approval/stop. Установка, привязка собственного ID и ремонт адаптера источника — отдельная ограниченная интеграционная работа.

## Общие представления и свидетельства с версиями
Не заполняй отдельно «План» и сводки проектов: они получаются из существующих
событий блоков. Фильтры — локальные настройки читателя; скрытая категория не
останавливает сбор. Перед использованием новых типизированных запросов или
предпосылок проверь фактическую поддержку контракта установленным сервисом.

На содержательной границе результата/предпосылки или изменения алгоритма приложи
имеющиеся квитанции артефакта, корректности или измерения с источником и применимой
версией/рабочей копией. Не превращай произвольный статус в доказательство, не
придумывай успех и не запускай проверки только ради заполнения панели. При работе
с неизвестными предпосылками сохраняй активность и объяснение расхождения; команд
управления исполнителем не появляется. Измерение для другого кода остаётся
историческим/устаревшим, а не становится свежим ускорением.
