# Готовность блоков и основания проверки

Исправлено отображение готовности по запросу владельца. На карте завершённые блоки имеют зелёную рамку, верхнюю полосу и метку «✓ Готово»; в Плане — зелёную отметку и статус. Выделение карточки сохраняется отдельно. Доступны результат, путь к доказательству, счётчик подтверждённых проверок и их основания. Проверено в действующем Waypoint через Chromium в обеих темах.

Причина прежнего экрана: N00–N07 были отмечены done со ссылками на отчёты, но результаты не были зарегистрированы по ID критериев как test.result. Область основного потока была заявлена только для N08. Поэтому в ранних блоках оставались пустыми переписка и индикаторы проверок. Это недочёт фиксации результатов предыдущей интеграции; пустой чат не доказывает ни выполнение, ни отсутствие работы.

Проведён аудит всех 47 критериев N00–N08. Для 44 найдены выполненные доказательства; исходный аудит 44/3 сохранён отдельно. Для трёх оставшихся выполнены новые адресные сценарии настоящего Chromium → HTTP → Store на явно синтетических данных:

- Предупреждение о начале работы до подтверждения входов сохраняется после позднего подтверждения и видно в Плане, Задании и Статусе. Ранее UI его не рисовал; добавлена отрисовка сохранённой истории.
- Нужная запись находится за 1200 более новыми неподходящими сообщениями в том же блоке, до лимита выдачи.
- Скрытый тип не увеличивает счётчик видимых новых сообщений; видимое контрольное сообщение увеличивает его ровно на один. Выделение и прокрутка сохраняются.

В рабочий журнал внесены 47 подтверждений по существующим node/test ID, с основаниями и уровнями доказательств. Поздняя регистрация явно помечена; старое время выполнения не выдумывалось. Исходная переписка, события и их привязки не переписаны. Нативные сообщения не заменялись искусственными заметками ради заполнения блоков. Новый UI прямо сообщает «Нет привязанных сообщений» и указывает на результат в «Приёмке».

Доказательства: `../evidence/BLOCK_CHECK_AUDIT.json` (исходный аудит), `BLOCK_CHECK_RESULTS.json` (47 сопоставлений), `COMPLETION_REGRESSIONS.json` (10 новых адресных проверок), `COMPLETION_UI.json` (6 проверок установленного UI). Снимки `completion-obsidian.png` и `completion-terracotta.png` показывают только N00 без текстов переписки. Новые синтетические сценарии не выдаются за проверку подключения Codex и не реконструируют прежний исторический инцидент.

Ссылка на изменённый UI-код в каталоге ALG-READ обновлена с сохранением старой версии и её доказательств. Остальные выполненные наборы не повторялись. Перезапуск Codex, сервиса и изменение глобальных скилов не требовались. N09 остаётся ожидающим третьего референса.

После обновления страницы браузер загрузит новые статические файлы. Для следующих работ локальная инструкция уточнена: заявлять свой участок до работы, использовать отдельную привязку подагента и записывать фактические проверки по ID критерия.
