# Waypoint — дорожная карта и неизменённая исходная база

**MIXED. Планирование выполнено; исполнители не запускались.**

В этом пакете две папки: `waypoint/` — исходный дизайн/код из уже переданного Pro-архива, без изменений; `roadmap/` — единый план его доведения до работающего продукта. Исходный `waypoint/CODEX_START.md` сохранён как часть истории поставки. Для следующего исполнения начните с **`roadmap/CODEX_START.md`**: он уточняет маршрут по новой карте, не отменяя архитектуру.

Откройте **`roadmap/PREVIEW.html`** для просмотра самой карты, **`roadmap/ROADMAP.md`** для обзора или **`roadmap/packets/WPT-C05.md`** для точного задания. В автономном просмотре нет живых агентов и вымышленных сообщений: видны реальные задания и декларации поставки C01–C04 из исходного отчёта. Это снимок плана, не действующая служба мониторинга.

Главный файл — **`roadmap/ROADMAP.plan.json`**, формат **`waypoint.plan/1`**. Он загружается текущим Waypoint напрямую. Задания, текстовая карта, группировки Runner и preview — его производные. Нет отдельного ручного переноса «плана из чата» в приложение.

Граф: поставленные C01–C04 → короткий **R00** → параллельная работа **C05/C06** → **C07**. Внутри C05/C06 есть один явный стык: **C05.3 → C06.3**; он не мешает подготовке C06.1/C06.2.

Проверить исходники: `cd waypoint && python3 tools/verify_package.py`. Проверить карту и её импорт через текущие Domain/Store/API: после установки тестовых зависимостей из поставленного `waypoint/pyproject.toml`, `cd roadmap && python3 tools/roadmap.py validate`. Результат текущего прогона — `roadmap/evidence/VALIDATION.json`. Проверки карты не заменяют целевую приёмку C05–C07.

Ничего не распаковывайте поверх неизвестной более новой рабочей копии. Сначала R00 устанавливает её фактическую базу. Не запускались Codex, Runner, наблюдение за сессиями, публикация в GitHub и изменения глобальных скилов.
