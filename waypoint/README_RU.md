# Waypoint — проектирование и исходная реализация

> Локальная интеграция 2026-10-17 выполняется поверх этой исходной поставки. Актуальный итог, реальные проверки и ограничения: [reports/RETURN_TO_CHAT_RU.md](reports/RETURN_TO_CHAT_RU.md). Запуск и приватное состояние: [LOCAL_RUN_RU.md](LOCAL_RUN_RU.md). Описание ниже сохраняет исходный контекст проектирования.

**Режим проекта: MIXED.** Подготовлен единый дизайн и запускаемая исходная реализация. Это не отчёт об установке на компьютере владельца. Действующие проекты, Codex, глобальные скилы и расписания этим пакетом не изменялись.

## Что открыть

**`preview.html`** — автономный интерфейс с вымышленным проектом. Это тот же HTML/CSS/JavaScript, который обслуживает локальный сервис. Вверху переключаются «Терракота» и «Обсидиан». Колесо над чатом прокручивает сообщения, над пустой картой меняет масштаб. Кнопка ↘ раскрывает внутренний граф; ↑ и хлебные крошки возвращают к родителю. Задание слева, приёмка справа, тесты сверху и статус снизу. Агенты и оркестраторы выделяют свои участки.

**`design/ARCHITECTURE.md`** — устройство продукта и принятые решения. **`design/CONTRACTS.md`** — схема карты, событий, локального API, привязок и конфликтов. **`design/IMPLEMENTATION_MAP.md`** честно отделяет реализованное от целевых доработок. **`CODEX_START.md`** — точка входа для локального Codex.

## Основной результат проектирования

Один локальный сервис Python/FastAPI/SQLite, один браузерный интерфейс и один формат карты/событий. Живой внутренний IPC VS Code и сохранённые JSONL-журналы — дополняющие источники для одной модели, а не две реализации Waypoint. Наблюдатель не запускает задачи, не утверждает планы и не запрещает агентам менять порядок работы.

Сообщения собираются из источника без пересказа моделью. Связь с произвольным блоком задаётся редкими сигналами при смене рабочего участка; глобальное session_id не подменяет отдельный ID агента. Неизвестная привязка остаётся неизвестной, а не дорисовывается убедительно.

План версионируется в локальной базе, экспорт в Git выполняется явно. Переписки и ключи не отправляются в Git/облако автоматически. Исходы тестов и их актуальность, произвольный статус и активность источника — разные сведения.

## Запуск сервиса с демонстрацией

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[test]'
python -m pytest -q
python -m waypoint --data "$HOME/.local/share/waypoint-demo" serve --demo
```

Открой локальную ссылку, напечатанную сервисом. В ней есть ключ чтения: не публикуй её. Для реального источника следуй `CODEX_START.md` и `design/OPERATIONS.md`; не копируй чужой HOME и не запускай новый App Server вместо наблюдаемого клиента.

## Проверки и оставшаяся работа

Фактические результаты текущего прогона находятся в `evidence/RESULTS.md` и машинных отчётах. Здесь выполнены программные/транзакционные проверки, синтетический Unix-собеседник, отдельный настоящий localhost HTTP и ввод мышью/клавиатурой в Chromium на автономном интерфейсе. Прямое открытие localhost браузером заблокировано политикой контейнера — эту интеграцию не объявляем пройденной.

Новая версия адаптера ещё не запускалась на живом Codex владельца. C05 доводит точную привязку исполнителя/событий и инкрементальную нормализацию; C06 — непрерывное чтение и обновление больших карт; C07 — сборку и приёмку на целевой машине. Это развитие одного решения. Ранее успешные P09–P11 подтверждают возможность выбранного механизма, но не заменяют проверку нового кода.

Два скила в `skills/` — кандидаты EN/RU, а не уже установленные глобальные инструкции. Их публикация и подключение выполняются отдельно по каноническому процессу.

## Сохранение и передача

Материалы сохранены в этом архиве и промежуточных контрольных точках разговора. Доступный в этой Pro-сессии Files API не предоставил записи в Library; существующие общий реестр капсул и inbox прочитаны, но **не изменены**. В `handoff/` находятся отдельные запросы публикации только для Waypoint, не новая очередь и не замена общего реестра. Установка/запуск внешних исполнителей не производились.
